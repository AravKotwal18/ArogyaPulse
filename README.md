# 🏥 ArogyaPulse

ArogyaPulse bridges the critical gap between frontline **ASHA (Accredited Social Health Activist)** community workers and remote district physicians. Operating in low-connectivity rural environments, the system provides instant vital signs analysis, automated risk stratification based on **WHO/NHM India** clinical parameters, and a real-time color-coded triage queue for doctors.

> **⚠️ Clinical Safety Notice:** ArogyaPulse is a screening aid, not a diagnostic tool. All risk assessments are generated by deterministic clinical rules and must be reviewed by a qualified medical professional before any clinical action is taken.

## Problem Statement

In rural India, ASHA (Accredited Social Health Activist) workers and primary health workers often lack immediate clinical decision support when recording patient vitals. Critical conditions such as severe hypoxia (SpO₂ < 90%), hypertensive crises, gestational pre-eclampsia, hypoglycemia, and high fever frequently go unrecognized or are delayed in escalation to district hospitals. This leads to preventable morbidity and mortality, especially among pregnant women and patients in remote villages.

There is a clear need for a lightweight, offline-capable, bilingual (English + Hindi) system that can:
- Instantly triage patients based on vital signs using WHO/NHM-aligned protocols
- Provide actionable clinical guidance to frontline workers
- Automatically alert higher-level doctors for high-risk cases
- Work reliably in low-connectivity rural settings

---

## Solution Overview

**ArogyaPulse** is a full-stack AI-assisted rural healthcare triage platform designed specifically for ASHA workers and district physicians.

### Key Capabilities
- **ASHA Patient Intake** – Simple form to record demographics + vitals (BP, SpO₂, Temperature, Glucose, Pregnancy status, Symptoms)
- **Intelligent Triage Engine** – Rule-based scoring system that evaluates risk in real time and generates:
  - Risk Score (0–100)
  - Risk Level (Low / Medium / High)
  - Detailed point breakdown
  - Clinical action recommendations
- **ASHA Bot AI** – Bilingual (English/Hindi) clinical decision support chatbot that answers questions about hypoxia, pre-eclampsia, fever, glucose management, etc.
- **Doctor Dashboard** – View, filter, and manage patients by village, risk level, and status
- **High-Risk Alerts** – Automatic notification simulation for district doctors when a High-risk patient is registered or updated
- **Village Clusters** – Geographic overview of patient load
- **Offline-first design** – SQLite database + static frontend that works even with intermittent connectivity

The system follows a clear clinical disclaimer: it is a **screening aid**, not a replacement for qualified medical judgment.

## 🔬 Triage Algorithm

The triage engine uses a **deterministic, point-based scoring system** adapted from WHO-IMNCI and NHM India guidelines:

| Vital Sign | Condition | Points | Action Level |
|---|---|---|---|
| **Blood Pressure** | Systolic ≥ 160 or Diastolic ≥ 100 | +40 | Urgent referral |
| | Systolic ≥ 140 or Diastolic ≥ 90 | +20 | Clinical review |
| | Pregnancy + BP ≥ 140/90 | +45 | Obstetric emergency |
| **SpO2** | < 90% | +35 | Emergency transport |
| | 90–94% | +15 | Priority review |
| **Glucose** | ≥ 200 mg/dL | +25 | Clinical assessment |
| | < 70 mg/dL | +30 | Immediate intervention |
| **Temperature** | ≥ 39.0°C | +15 | Infection screening |
| | < 35.0°C | +20 | Urgent assessment |

### Risk Stratification
| Score | Level | Response |
|---|---|---|
| **≥ 50** | 🔴 High | Immediate doctor review, alert triggered |
| **25–49** | 🟡 Medium | Priority review within 24 hours |
| **0–24** | 🟢 Low | Routine follow-up |

> Score is capped at 100. Every evaluation includes a clinical disclaimer and protocol reference.

## 🔒 Safety & Audit

- **Clinical Disclaimers** on every triage result and AI chat response
- **Immutable Audit Trail** — every patient registration, status change, risk escalation, and doctor note is logged
- **Request Logging Middleware** — every API call tracked with method, path, status code, and response time
- **Global Exception Handling** — consistent error JSON responses; no stack trace leaks in production

---

## 🌐 Offline-First Support

ASHA workers in rural India often operate without reliable connectivity. ArogyaPulse supports:

1. **Batch Sync** — `POST /api/sync` accepts multiple offline-captured patient records at once
2. **Duplicate Detection** — Records with the same patient name + village within a 30-minute window are flagged as conflicts
3. **Auto-Triage** — Every synced record is automatically triaged on arrival
4. **Device History** — Each device's sync history is tracked for accountability

## 🚀 Quick Start

### Prerequisites
- [.NET 10.0 SDK](https://dotnet.microsoft.com/download)

### Setup
```bash
# Clone the repository
git clone https://github.com/AravKotwal18/ArogyaPulse.git
cd ArogyaPulse

# Restore dependencies
dotnet restore

# Run the application
dotnet run
```

The API will start at `http://localhost:5045`. The database (SQLite) is created automatically on first run with sample seed data.

### Environment
| File | Purpose |
|---|---|
| `appsettings.json` | Connection string, logging configuration |
| `arogyapulse.db` | SQLite database (auto-created) |
